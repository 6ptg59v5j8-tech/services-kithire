# DBAVL — Equipment Hire

A separate Cloudflare Pages website for DBAVL. It is independent of the Daniel Burden portfolio.

## Included
- Responsive public equipment catalogue and individual item pages
- Private dashboard at `/admin` (there is deliberately no admin link on the public site)
- Editable site content, logo/favicon/about photograph, social links and section visibility
- Equipment create/edit/delete, weekly-only pricing, manual stock quantities, image upload and gallery uploads
- Category list management, hire information, announcement banner and homepage text controls
- Enquiry basket with estimated weekly total, date and customer details
- Enquiries saved in D1 and visible in the admin dashboard
- Optional business and customer email notifications through Resend
- Cloudflare D1 database and R2 image storage

## Important business behaviour
- Pricing is weekly only.
- Stock quantities are controlled manually in the admin dashboard.
- The basket total is an estimate only. Submitting an enquiry does not book equipment, reserve stock or confirm a hire.
- DBAVL reviews the enquiry and confirms availability personally.
- Enquiries are stored in D1 even if email notifications have not been configured.

## Deploying to your existing DBAVL Cloudflare project
1. Upload the contents of this folder to your existing DBAVL GitHub repository, replacing the matching website files.
2. **Keep your real working `wrangler.toml` database ID.** The included file may contain the setup placeholder `REPLACE_WITH_YOUR_NEW_D1_DATABASE_ID`; do not deploy that placeholder. Retain the actual database ID and your existing `DB` and `MEDIA` bindings.
3. In your existing `dbavl-db` D1 database, run `DBAVL-UPDATE.sql` once. It assumes `price_per_week` and `quantity_available` were added during the earlier setup. If they were not, run the optional ALTER statements in that file only if those columns are absent. Do not run an ALTER statement for a column that already exists.
4. Confirm the Pages project has D1 binding `DB` pointing to `dbavl-db` and R2 binding `MEDIA` pointing to `dbavl-media`.
5. Keep your existing `ADMIN_EMAIL` and `ADMIN_PASSWORD` environment variables.
6. Set these Pages environment variables to enable outgoing email:
   - `ENQUIRY_EMAIL` = `enquiries@dbavl.co.uk`
   - `RESEND_API_KEY` = your Resend API key
   - `EMAIL_FROM` = a sender address verified in Resend
7. Deploy. Test `/admin`, add/edit a test item, and submit a test enquiry.

## New installation
For a completely new D1 database, run `schema.sql` once. Update the database ID in `wrangler.toml` with the real ID generated by Cloudflare and configure the D1/R2 bindings and admin secrets.

## Email behaviour
Without `RESEND_API_KEY` and a verified `EMAIL_FROM`, enquiries are still saved in D1 and appear in Admin → Enquiries, but email notifications will not be sent. Email delivery should be tested after configuration.

## Security and separation
- Do not connect this project to the portfolio D1 database or R2 bucket.
- Do not expose `ADMIN_PASSWORD` in website files or commit it to GitHub.
- The public site intentionally has no admin button or link.
